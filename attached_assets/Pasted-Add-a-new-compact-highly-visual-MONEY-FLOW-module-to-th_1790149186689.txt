Add a new compact, highly visual “MONEY FLOW” module to the Qureshi Finance Search/Stock Detail page.

GOAL:
I do NOT want a wall of numbers. The module should visually explain whether a stock/crypto move appears to be supported by actual capital flows, ETF activity, volume, derivatives positioning, or a short squeeze.

DESIGN:
Make it look like a professional Bloomberg/TradingView-style mini dashboard that fits naturally into the existing Qureshi Finance UI.

1. MONEY FLOW SUMMARY
At the top, display a large visual status:
• STRONG INFLOW
• INFLOW
• NEUTRAL
• OUTFLOW
• STRONG OUTFLOW

Use a horizontal flow meter/gauge rather than just a number.

Underneath show:
“Money Flow Strength”
with a visual score from 0–100.

IMPORTANT:
This score must be calculated from real available data. NEVER fabricate or estimate missing data without clearly labeling it as an estimate.

2. ETF FLOW PRESSURE — VISUAL BAR CHART
For stocks, identify major ETFs that hold the selected stock.

Examples:
• SPY
• QQQ
• IWM
• sector ETFs
• relevant industry ETFs

Show a horizontal bar chart showing:
ETF → estimated flow contribution to the selected stock

Example:
QQQ       ███████████  Positive
SPY       ███████      Positive
Sector ETF ████        Negative

Calculate estimated exposure using:
ETF net flow × stock weight in the ETF

Clearly label this as:
“ETF Flow Exposure — Estimated”

Do NOT represent ETF flows as direct buying/selling of the individual stock.

3. ETF NET FLOW TREND
Add a compact line/area chart showing ETF net flows over approximately:
• 5 trading days
• 20 trading days when data is available

Allow the user to switch between 5D and 20D.

Make the chart visually obvious when flows are accelerating, weakening, or reversing.

4. RELATIVE VOLUME
Add a visual gauge:

Relative Volume
1.0x = normal
>1.5x = elevated
>2.0x = strong
>3.0x = extreme

Show the current relative volume visually.

Also show:
“Volume confirms move”
or
“Volume does NOT confirm move”

5. PRICE VS MONEY FLOW
Create a small two-line visual comparing:
• Price
• Money/ETF Flow

Use the same time period.

Highlight divergences.

Examples:
PRICE ↑ + FLOW ↑ = flow confirmation
PRICE ↑ + FLOW ↓ = potential divergence
PRICE ↓ + FLOW ↑ = accumulation possibility
PRICE ↓ + FLOW ↓ = distribution/weakness

Do NOT automatically call these buy/sell signals.

6. SHORT SQUEEZE / POSITIONING PANEL
For stocks where short-interest/borrow/short-volume data is available, show visual indicators for:
• Short interest
• Short volume
• Days to cover
• Change in short interest
• Relative volume

For crypto, instead show:
• Open Interest
• Funding Rate
• Long/Short positioning
• Liquidations

Use simple visual arrows:
↑ increasing
↓ decreasing
→ neutral

7. LIQUIDATION VISUAL — CRYPTO ONLY
For Bitcoin and other supported crypto assets, create a visual split bar:

LONG LIQUIDATIONS | SHORT LIQUIDATIONS

Example:

LONG  ████████  $120M
SHORT ███       $45M

Also show whether the recent move appears to have been accompanied by:
• Short covering
• Long liquidation
• Both
• Neither / insufficient data

Do NOT claim a squeeze occurred unless the underlying data supports it.

8. PRIMARY FLOW DRIVER
At the bottom, create a compact explanation box:

“PRIMARY MOVE DRIVER”

Possible factual classifications:
• Spot/ETF flow
• Elevated volume
• Short covering
• Long liquidation
• Derivatives positioning
• Broad market movement
• Sector movement
• Mixed
• Insufficient data

Explain WHY in 1–2 sentences using the actual data.

Example:

“BTC is rising while short liquidations are elevated and open interest is falling, suggesting short covering is contributing to the move.”

Do NOT make unsupported conclusions.

9. DATA QUALITY
This is extremely important.

Never invent:
• ETF flows
• volume
• open interest
• funding
• short interest
• liquidations
• institutional flows

If a data source is unavailable, display:
“Data unavailable”

If data is delayed, display:
“Delayed data”

If a calculation is an estimate, clearly label:
“Estimated”

Show the timestamp/source for each major data category.

10. EQUITIES VS CRYPTO

Automatically detect the asset type.

For EQUITIES show:
• ETF flow exposure
• ETF flow trend
• Relative volume
• Price vs flow
• Short interest/short volume when available
• Sector flow
• Market flow

For CRYPTO show:
• Spot ETF flows where applicable
• Open interest
• Funding rate
• Long/short positioning
• Liquidations
• Volume
• Price vs flow
• ETF flow trend

Do not display irrelevant metrics.

12. INTERACTION

Allow users to hover/tap each visual element to see:
• exact value
• timeframe
• timestamp
• data source
• whether the value is actual or estimated

Keep the module compact enough that it does not dominate the stock page.

13. API / DATA ARCHITECTURE

Before writing new code, inspect the existing Qureshi Finance codebase and determine what market-data APIs are already being used.

Reuse existing API infrastructure whenever possible.

Create a clean abstraction such as:

getMoneyFlowData(symbol)

which returns the appropriate data for stocks or crypto.

Cache expensive API requests and respect provider rate limits.

Do not expose API keys in frontend code.

14. ERROR HANDLING

If one data source fails, the entire Money Flow module should NOT break.

Show available data while displaying:
“Some data unavailable”

Do not substitute fake values.

15. TESTING

Test the module with:

BTC

TSLA

Verify that:
• crypto metrics appear for BTC
• equity metrics appear for stocks
• ETF exposure is calculated correctly
• unavailable data is clearly marked
• charts update when changing symbols
• timestamps are displayed
• no fabricated data appears
• existing Qureshi Finance functionality is not broken

IMPORTANT:
Do not redesign the entire website.

Only add and integrate this Money Flow module into the existing Search/Stock Detail experience while matching the existing Qureshi Finance visual design.

The final result should feel like a professional visual “capital flow dashboard,” not a spreadsheet of statistics.
