4. HISTORICAL SEARCH

Search historical data for previous periods that resemble the current pattern.

For every historical candidate:

* Use the same lookback length.
* Never use future information when determining similarity.
* Exclude overlapping candidates when necessary.
* Exclude the current period.
* Prevent look-ahead bias.
* Require sufficient forward data after the candidate.

Calculate similarity using multiple components:

1. Normalized price-path similarity
2. Return correlation
3. Volatility similarity
4. Momentum similarity
5. Drawdown similarity
6. Volume/relative-volume similarity when available

Create a weighted similarity score.

Example:

price_similarity = correlation(normalized_current, normalized_historical)

return_similarity = correlation(current_returns, historical_returns)

volatility_similarity = similarity(current_volatility, historical_volatility)

momentum_similarity = similarity(current_momentum, historical_momentum)

drawdown_similarity = similarity(current_drawdown, historical_drawdown)

overall_similarity =
0.45 * price_similarity +
0.20 * return_similarity +
0.15 * volatility_similarity +
0.10 * momentum_similarity +
0.10 * drawdown_similarity

Make these weights configurable in the backend.

Do NOT claim these exact weights are Forecaster’s weights. They are our implementation.

total weighted qualifying outcomes

bear_probability =
weighted bearish outcomes /
total weighted qualifying outcomes

weighted neutral outcomes /

22. DATA LEAKAGE PROTECTION

This is CRITICAL.

The historical pattern engine must NEVER use future information when evaluating historical predictions.

For example:

If evaluating a pattern from January 2019:

The algorithm may only use data that existed at that time to calculate the pattern.

Future candles may ONLY be used to determine the outcome after the prediction point.

Build automated tests specifically for look-ahead bias.
