PRODUCTION READINESS GATE

The application passes production readiness only if ALL of the following critical requirements pass.

1. APPLICATION STARTUP

PASS requires:

* Production process starts successfully.
* Production process remains running.
* No fatal startup exceptions.
* Correct production startup command.
* Correct environment configuration.
* Server binds to 0.0.0.0.
* Server uses the deployment-provided PORT.
* No development server is being used unintentionally.

2. DEPLOYMENT

PASS requires:

* Production deployment completes successfully.
* Actual deployment target is verified.
* Deployment target remains the intended VM deployment.
* A subsequent harmless project update/redeploy does NOT change the deployment target to Cloud Run/Autoscale.
* Deployment remains healthy after stabilization.

If the deployment target changes unexpectedly, this is a FAIL.

3. DATABASE

PASS requires:

* Production database is reachable.
* Required migrations are applied.
* Required bot tables exist.
* Application can read from the database.
* Application can write to the database.
* No unresolved schema migration errors exist.

4. API

PASS requires:

* Core API endpoints respond successfully.
* Authentication works where applicable.
* Database-backed API operations work.
* No fatal API errors occur during basic production testing.

5. FRONTEND

PASS requires:

* Application loads successfully.
* Critical pages load.
* No fatal JavaScript/runtime errors preventing core functionality.
* API communication works.
* Authentication/session behavior works where applicable.

6. TRADING BOT SYSTEM

PASS requires:

* Bot services initialize successfully.
* Required bot tables exist.
* Scheduler initializes successfully.
* Scheduler does not create duplicate workers/processes.
* Bot execution does not crash immediately.
* Required market-data connections initialize successfully.
* Trading signals can be generated using the existing architecture.

Do NOT change trading strategy logic while performing this verification.

7. REAL-TIME CONNECTIONS

Where the application uses WebSockets or other real-time connections:

* Connection can be established.
* Connection remains functional.
* No deployment/proxy configuration is preventing the connection.
* No persistent connection failure exists.

8. ENVIRONMENT VARIABLES / SECRETS

Verify that every REQUIRED production environment variable exists.

Do NOT expose secret values.

Report only:

PASS — present

or

FAIL — missing

Never print secret values into the response.

9. ERROR LOGS

Review production logs.

Separate findings into:

CRITICAL:
Prevents production operation.

WARNING:
Should be addressed but does not prevent production operation.

INFORMATIONAL:
Not a production blocker.

A WARNING or INFORMATIONAL item must NOT automatically change the final result to NOT READY.

10. DATA INTEGRITY

Verify that:

* Existing production data is accessible.
* No destructive migration occurred.
* No required tables were accidentally dropped.
* No obvious schema/data corruption exists.
